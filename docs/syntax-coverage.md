# Syntax and semantic coverage ledger

This is the mechanism-level review ledger behind
[language-support.md](language-support.md). It records the current `main`
implementation against Vim v9.2.1015; it is not an exhaustive list of accepted
spellings or individual tests. Error-code ownership belongs in
[vim-error-code-support.md](vim-error-code-support.md), and test commands belong
in [testing.md](testing.md).

Status words have strict meanings:

- **Completed**: all owned parsing, static semantics, and diagnostics are
  evidenced; explicitly opaque or runtime-dependent behavior is N/A.
- **Implemented**: linked repository evidence exercises the stated behavior.
- **Partial — TODO**: some behavior exists; the remaining boundary is stated.
- **Deferred — TODO**: deliberately unsupported for 1.0 or unsafe to infer.
- **N/A**: the mechanism has no applicable static semantics.

`D/R/S/T` means declarations, references, scopes, and types. Parsing,
semantics, and diagnostics are tracked separately: producing an AST does not
prove semantic or diagnostic coverage. Vim evidence links are pinned to
v9.2.1015.

## Evidence and maintenance rules

1. Add a row only for a new parser mechanism. Add another spelling to the
   existing row when it uses the same mechanism.
2. Every repository evidence link must resolve to a current source or test
   file. Prefer a file-level link; name a test only when a disputed claim needs
   that precision, and verify the symbol still exists.
3. A parser test cannot close a semantic TODO. Declarations, references,
   scopes, types, and diagnostics require evidence from their owning layer.
4. Shared recovery evidence applies to both roots only when the implementation
   is shared. Keep dialect-specific boundaries explicit.
5. Every version-sensitive claim must name the Vim patch and link its pinned
   source or help evidence. Behavior observed on a newer Vim is not backported.
6. Mark a row **Completed** only when it contains no `Partial`, `Deferred`, or
   `TODO` status. Do not create a TODO for opaque or runtime-dependent behavior
   that the server intentionally keeps unknown.
7. A deferred cross-package feature must name its missing immutable input or
   source-language contract. Do not make `analysis` depend on workspace state
   merely to infer a dynamic legacy value, and do not assign deferred callback
   calls to an enclosing function that does not execute them.
