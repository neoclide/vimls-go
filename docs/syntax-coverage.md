# Syntax and semantic coverage ledger

This ledger is the review boundary for the syntax requirements in
`language-support.md`. It describes the current `main` implementation against
Vim v9.2.1015; it is not a promise that producing an AST implies complete
language-server semantics.

Status words have strict meanings:

- **Implemented**: the named tests directly exercise the stated behavior.
- **Partial — TODO**: some behavior exists, but the text after `TODO` remains
  required before the row is complete.
- **Deferred — TODO**: deliberately unsupported for 1.0 or unsafe to infer.
- **N/A**: the mechanism has no declarations, references, scopes or types.

Semantic cells use `D` for declarations, `R` for references, `S` for scopes and
`T` for types. Diagnostics are separate because parse acceptance and semantic
validity are independent. Test names are stable evidence pointers; line
numbers are intentionally omitted. Official paths and help tags refer to the
read-only [Vim v9.2.1015 source tree](https://github.com/vim/vim/tree/v9.2.1015).
Repository paths are relative to the [project root](../); test function names
make each reference searchable without coupling the ledger to changing line
numbers.

## Maintenance rules

1. Add a row only when a new parser mechanism is introduced. Add evidence to
   an existing row for another spelling handled by that mechanism.
2. A positive parser test cannot remove a semantic `TODO`; declarations,
   references, scopes, types and diagnostics need their own evidence.
3. Shared recovery tests cover both roots only when the implementation is
   actually shared. Dialect-specific boundaries retain separate evidence.
4. Every version-sensitive claim names the Vim patch and the matching pinned
   source/help/test location. Observations from a newer Vim are not backported.
5. A completed row must contain no `Partial`, `Deferred`, or `TODO` status.
