# Developer tools

This document describes all internal developer tools under `tools/`, their
purposes, invocation options, and integration with `Makefile` and CI workflows.

## Tool overview

| Tool | Package | Role | Invoked by | Key targets / workflows |
| --- | --- | --- | --- | --- |
| `tools/covercheck` | `main` | Verifies statement test coverage percentage | Makefile | `make coverage`, `make check` |
| `tools/genmetadata` | `main` | Extracts Vim runtime metadata into Go data tables | Makefile | `make metadata-refresh`, `make metadata-check` |
| `tools/geneventdocs` | `main` | Merges Vim and Neovim autocmd event documentation | Makefile | `make eventdocs-refresh`, `make eventdocs-check` |
| `tools/release` | `main` | Validates changelog and builds multi-platform release archives | Makefile / CI | `make release`, `.github/workflows/release.yml` |
| `tools/helpdoc` | `main` | Measures and exports runtime help extraction as Markdown & JSON | Manual | Help extraction benchmarks & diagnostics |
| `tools/diagnosticscan` | `main` | Batch-scans runtimepaths for error-level vimls-go diagnostics | Manual | Ecosystem triage & batch analysis |
| `tools/benchlegacy` | `benchlegacy` (module) | Compares Legacy parser performance with go-vimlparser | Manual | Performance comparisons & CPU/heap profiling |
| `tools/benchreport` | `main` | Analyzes benchmark output and enforces regression gates | CI / Manual | `.github/workflows/scheduled.yml` |

## Tools used in Makefile

### 1. `tools/covercheck`

Validates statement test coverage from a Go coverage profile against a required
minimum percentage.

#### Makefile usage

`covercheck` is run by `make coverage` (and transitively by `make check`):

```makefile
COVERAGE_MIN ?= 90

coverage:
	$(GO) test $(GO_MOD) -coverpkg=./internal/... -coverprofile=coverage.out ./...
	$(GO) run $(GO_MOD) ./tools/covercheck -profile coverage.out -min $(COVERAGE_MIN)
```

- `make coverage`: Generates `coverage.out` covering all `internal/...` packages,
  then runs `covercheck` requiring at least `COVERAGE_MIN` (default: 90%).
- `make check`: Runs formatting checks, unit tests, race detection, vet,
  `coverage`, and binary builds in sequence.

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-profile <file>` | `coverage.out` | Path to the Go coverage profile generated by `go test -coverprofile`. |
| `-min <float>` | `85` | Minimum required statement coverage percentage. |

#### Exit codes

- `0`: Coverage percentage is greater than or equal to `-min`.
- `1`: Coverage percentage falls below `-min`.
- `2`: Unable to read or parse the coverage profile file.

#### Direct invocation

```sh
go test -coverpkg=./internal/... -coverprofile=coverage.out ./...
go run ./tools/covercheck -profile coverage.out -min 90
```

### 2. `tools/genmetadata`

Generates internal Go data tables and Vim option validation scripts from a
pinned official Vim checkout (`v9.2.1015`, commit
`5ab969f719bb09555e90e8dff8c94fc37bcbf2ae`).

#### Generated files

All files are written to `internal/vimdata/` (or `-output-dir`):
- `commands_generated.go`: Ex commands, short names, argument counts, address
  specifications, and command flags.
- `functions_generated.go`: Built-in function signatures, parameter counts and
  types, and return types.
- `options_generated.go`: Vim options, short names, types, scopes, and default values.
- `options_set_generated.vim`: Vim script used to validate option settings against
  Vim's runtime behavior.
- `variables_generated.go`: Standard `v:` variables, types, and read-only status.

#### Makefile usage

```makefile
metadata-refresh: eventdocs-refresh
	@test -n "$(VIM_SOURCE)" || (echo "set VIM_SOURCE to the official Vim checkout" >&2; exit 1)
	$(GO) run $(GO_MOD) ./tools/genmetadata -vim-root "$(VIM_SOURCE)"

metadata-check: eventdocs-check
	@test -n "$(VIM_SOURCE)" || (echo "set VIM_SOURCE to the official Vim checkout" >&2; exit 1)
	@set -eu; \
	metadata_tmp="$$(mktemp -d)"; \
	trap 'rm -rf "$$metadata_tmp"' EXIT; \
	$(GO) run $(GO_MOD) ./tools/genmetadata -vim-root "$(VIM_SOURCE)" -output-dir "$$metadata_tmp"; \
	cmp internal/vimdata/commands_generated.go "$$metadata_tmp/commands_generated.go"; \
	cmp internal/vimdata/functions_generated.go "$$metadata_tmp/functions_generated.go"; \
	cmp internal/vimdata/options_generated.go "$$metadata_tmp/options_generated.go"; \
	cmp internal/vimdata/options_set_generated.vim "$$metadata_tmp/options_set_generated.vim"; \
	cmp internal/vimdata/variables_generated.go "$$metadata_tmp/variables_generated.go"
	$(GO) test $(GO_MOD) -count=1 ./internal/vimdata ./tools/genmetadata ./tools/geneventdocs ./internal/vimhelp
```

- `make metadata-refresh`: Updates generated files in `internal/vimdata/`. Requires
  `VIM_SOURCE` and `NEOVIM_SOURCE` (for eventdocs).
- `make metadata-check`: Generates metadata into a temporary directory and
  compares (`cmp`) against committed files to ensure no uncommitted drift. Also
  runs unit tests for metadata packages.

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-vim-root <dir>` | `$VIM_SOURCE` | Path to the official Vim Git checkout. Must contain tag `v9.2.1015`. |
| `-output-dir <dir>` | `internal/vimdata` | Directory where generated files are written. |

#### Direct invocation

```sh
go run ./tools/genmetadata -vim-root /path/to/vim -output-dir internal/vimdata
```

### 3. `tools/geneventdocs`

Extracts autocmd event definitions, aliases, and documentation from both Vim and
Neovim source repositories and merges them into unified Go metadata.

#### Generated files

- `internal/vimdata/autocmd_docs_generated.go`: Structured documentation table
  containing 156 unique events (127 Vim events and 29 Neovim-only events).

#### Pinned upstream revisions

- **Vim**: `v9.2.1015` (`5ab969f719bb09555e90e8dff8c94fc37bcbf2ae`), reading
  `src/autocmd.c` and `runtime/doc/autocmd.txt`.
- **Neovim**: `v0.12.0-2035-g73923b0dd8` (`73923b0dd85bb936ba2f63ee916dabaa0603340d`),
  reading `src/nvim/auevents.lua` and help docs.

#### Makefile usage

```makefile
eventdocs-refresh:
	@test -n "$(VIM_SOURCE)" || (echo "set VIM_SOURCE to the official Vim checkout" >&2; exit 1)
	@test -n "$(NEOVIM_SOURCE)" || (echo "set NEOVIM_SOURCE to the official Neovim checkout" >&2; exit 1)
	$(GO) run $(GO_MOD) ./tools/geneventdocs -vim-root "$(VIM_SOURCE)" -neovim-root "$(NEOVIM_SOURCE)"

eventdocs-check:
	@test -n "$(VIM_SOURCE)" || (echo "set VIM_SOURCE to the official Vim checkout" >&2; exit 1)
	@test -n "$(NEOVIM_SOURCE)" || (echo "set NEOVIM_SOURCE to the official Neovim checkout" >&2; exit 1)
	@set -eu; \
	eventdocs_tmp="$$(mktemp)"; \
	trap 'rm -f "$$eventdocs_tmp"' EXIT; \
	$(GO) run $(GO_MOD) ./tools/geneventdocs -vim-root "$(VIM_SOURCE)" -neovim-root "$(NEOVIM_SOURCE)" -output "$$eventdocs_tmp"; \
	cmp internal/vimdata/autocmd_docs_generated.go "$$eventdocs_tmp"
```

- `make eventdocs-refresh`: Regenerates `autocmd_docs_generated.go`.
- `make eventdocs-check`: Compares a temporary generation against the committed
  file to ensure consistency in CI.

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-vim-root <dir>` | `""` | Path to official Vim checkout. |
| `-neovim-root <dir>` | `""` | Path to official Neovim checkout. |
| `-output <file>` | `internal/vimdata/autocmd_docs_generated.go` | Destination Go file. |

#### Direct invocation

```sh
go run ./tools/geneventdocs -vim-root /path/to/vim -neovim-root /path/to/neovim
```

### 4. `tools/release`

A release packaging tool with two modes:
1. **Changelog verification** (`-check-changelog`): Validates that `CHANGELOG.md`
   contains a unique, non-empty release notes section matching `-version`.
2. **Release archive building**: Cross-compiles `vimls` binaries for multiple
   operating systems and architectures, bundles license files and documentation,
   produces `.tar.gz` and `.zip` archives, and generates `checksums.txt`.

#### Target matrix

- `darwin/amd64`, `darwin/arm64`
- `linux/amd64`, `linux/arm64`, `linux/armv7`
- `windows/amd64`, `windows/arm64`
- `freebsd/amd64`

#### Makefile usage

In `make release`:

```makefile
release:
	@set -eu; \
	release_tag="v$$(cat VERSION)"; \
	...
	$(GO) run $(GO_MOD) ./tools/release -version "$$release_tag" -check-changelog; \
	git remote get-url "$$RELEASE_REMOTE" >/dev/null; \
	git tag -a "$$release_tag" -m "Release $$release_tag"; \
	git push "$$RELEASE_REMOTE" "refs/tags/$$release_tag:refs/tags/$$release_tag"
```

- `make release`: Ensures the git worktree is clean, validates the release notes
  in `CHANGELOG.md` via `tools/release -check-changelog`, creates the annotated git tag,
  and pushes the tag to `RELEASE_REMOTE` (default: `origin`).

#### CI usage

In `.github/workflows/release.yml`:
```sh
go run -mod=readonly ./tools/release -version "$TAG" -epoch "$(git log -1 --format=%ct)" \
  -output-dir dist -notes-output dist/notes.md
```
Builds all platform archives deterministically using `git log` commit timestamp
for `SOURCE_DATE_EPOCH`, extracts release notes to `dist/notes.md`, and prepares
assets for GitHub Release upload.

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-version <tag>` | `""` | Release tag, e.g. `v0.2.0` (required). |
| `-check-changelog` | `false` | Validate `CHANGELOG.md` section for `-version` without building assets. |
| `-epoch <timestamp>` | `0` | `SOURCE_DATE_EPOCH` Unix timestamp for reproducible archive headers (required when building). |
| `-output-dir <dir>` | `dist` | Destination directory for archives and `checksums.txt`. |
| `-notes-output <file>` | `""` | Optional destination path for extracted CHANGELOG release notes. |

#### Direct invocation

```sh
# Validate changelog only
go run ./tools/release -version v0.2.0 -check-changelog

# Build release assets locally
go run ./tools/release -version v0.2.0 -epoch $(date +%s) -output-dir /tmp/dist
```

## Standalone tools

### 5. `tools/helpdoc`

Inspects and benchmarks runtime help extraction from `doc/*.txt` across
directories on a Vim `runtimepath`.

#### Capabilities

- Extracts help documentation for plugin functions (`*plugin#name()*`),
  variables (`*g:name*`), Ex commands, and `<Plug>` mappings.
- Converts raw Vim help prose into formatted Markdown.
- Measures discovery, read, markdown conversion, and memory allocations across
  `-repeat` cycles.
- Outputs a human-readable Markdown report to `-output` and detailed JSON
  measurements to stdout.

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-runtimepath <string>` | `""` | Comma-separated runtimepath roots (escaped commas supported as `\,`). |
| `-runtimepath-file <file>` | `""` | Read runtimepath from a text file (line breaks removed). |
| `-output <file>` | `""` | Destination Markdown report file (required). |
| `-repeat <int>` | `5` | Number of complete discovery/read/extraction benchmark runs. |

#### Direct invocation

```sh
go run ./tools/helpdoc \
  -runtimepath "$HOME/.vim/pack/vendor/start/tpope-surround" \
  -output /tmp/surround-help.md \
  -repeat 3 > /tmp/surround-stats.json
```

### 6. `tools/diagnosticscan`

Scans Vim scripts across a given `runtimepath` and reports error-level
vimls-go diagnostics.

#### Capabilities

- Discovers script files under `plugin/**/*.vim`, `autoload/**/*.vim`, and
  `import/**/*.vim`.
- Applies configuration-aware analysis (`workspace.IsConfigFile`) or standard
  analysis.
- Filters out non-error warnings/hints and reports file, line, column, error code,
  and diagnostic message.
- Useful for large-scale offline triage of plugin ecosystems or verifying analyzer
  behavior on real-world scripts.

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-runtimepath <string>` | `""` | Comma-separated Vim runtimepath to search (required). |
| `-output <file>` | stdout | File destination for findings (defaults to stdout). |

#### Direct invocation

```sh
go run ./tools/diagnosticscan \
  -runtimepath "$HOME/.vim/pack/plugins/start/my-plugin" \
  -output /tmp/diagnostics.txt
```

### 7. `tools/benchlegacy`

A standalone Go module (`tools/benchlegacy/go.mod`) designed to benchmark legacy
Vim script parsing in `vimls-go` against [go-vimlparser](https://github.com/vim-jp/go-vimlparser).

#### Capabilities

- Compares `vimls-go` and `go-vimlparser` on clean legacy files from Vim `v9.2.1015`.
- Benchmarks parallel worker throughput (1, 2, or 4 workers).
- Generates CPU and allocation pprof profiles via `TestProfileVimlsBatch`.

#### Usage

Because `benchlegacy` references `go-vimlparser` without polluting `vimls-go`'s
root `go.mod`, it uses a temporary `go.work`:

```sh
bench_work=$(mktemp -d)
go work init /path/to/vimls-go /path/to/vimls-go/tools/benchlegacy /path/to/go-vimlparser
cd /path/to/vimls-go/tools/benchlegacy

# Run comparative benchmark
GOMAXPROCS=1 GOWORK="$bench_work/go.work" \
  go test -run '^$' \
  -bench '^BenchmarkLegacyParsers/(vimls-go|go-vimlparser)-common$' \
  -benchmem -benchtime=1x -count=5 -args -root /path/to/vim/runtime

# Profile vimls-go batch parsing
profile_dir=$(mktemp -d)
GOWAXPROCS=1 GOWORK="$bench_work/go.work" \
  go test -count=1 -run '^TestProfileVimlsBatch$' -args \
  -profile-dir "$profile_dir" -profile-workers 1 -profile-runs 5 \
  -root /path/to/vim/runtime

go tool pprof -top "$profile_dir/cpu.pprof"
```

For full details, see [`tools/benchlegacy/README.md`](../tools/benchlegacy/README.md).

### 8. `tools/benchreport`

Parses Go benchmark outputs (`go test -bench`), calculates summary statistics
(median, P95, allocations), and verifies that changes do not violate regression
gates against a baseline run.

#### Capabilities

- Parses standard Go benchmark lines (`Benchmark... ns/op B/op allocs/op`).
- Computes sample median and nearest-rank P95 latency.
- Regression gates (with `-baseline` and $\ge 20$ samples):
  - Sample median latency increase $\le 15\%$.
  - Nearest-rank P95 latency increase $\le 15\%$.
  - Median bytes/op increase $\le 20\%$.
  - Median allocations/op increase $\le 20\%$.
  - `BenchmarkCompletionLatency` sample median $\le 100\text{ ms}$.

#### CI usage

Used in `.github/workflows/scheduled.yml`:
```sh
go run ./tools/benchreport \
  -input artifacts/benchmark_current.txt \
  -baseline artifacts/benchmark_baseline.txt \
  2>&1 | tee -a artifacts/benchmark_report.txt
```

#### Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `-input <file>` | stdin | Input benchmark output file. |
| `-baseline <file>` | `""` | Baseline benchmark output file; enables regression verification. |

#### Direct invocation

```sh
# Summarize single benchmark run
go run ./tools/benchreport -input current_benchmarks.txt

# Compare with baseline and check regression gates
go run ./tools/benchreport -input current_benchmarks.txt -baseline baseline_benchmarks.txt
```
